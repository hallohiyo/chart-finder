# chart-finder

원하는 차트 조건을 자유롭게 조합해서, **그 조건에 가장 근접한 종목**을 뽑아주는 스크리너.
한국(KOSPI/KOSDAQ)과 미국(NYSE/NASDAQ) 시장을 모두 지원하고, CLI와 웹 UI 두 가지로 쓸 수 있다.

## 뭐가 다른가: 근접도 점수

일반 스크리너는 조건을 참/거짓으로 잘라서 하나라도 못 맞추면 결과에서 사라진다.
여기서는 조건마다 **0~1 점수**를 매기고 가중 평균으로 랭킹한다.

```
RSI(14) < 30 조건에서
  RSI 25 → 1.00 (충족)
  RSI 31 → 0.96 (아깝게 미달, 여전히 후보)
  RSI 45 → 0.02
```

덕분에 "5개 조건 중 4.5개를 만족하는 종목"이 자연스럽게 상위에 올라온다.
기존 방식이 필요하면 `--strict` (웹 UI에서는 '엄격 모드')를 켜면 된다.

## 실행 (Windows)

**`주식찾기.bat` 을 더블클릭한다.** 처음 한 번은 준비 작업(가상환경 생성 + 설치)을
알아서 하고 몇 분 걸리며, 그다음부터는 바로 창이 뜬다. 검은 명령창은 남지 않는다.

- `주식찾기.bat` — 기본 화면
- `고급화면.bat` — 조건을 직접 고르는 화면

바탕화면에 두고 쓰려면 파일을 **우클릭 → 바로 가기 만들기** 후 바로가기를 옮긴다
(파일 자체를 옮기면 안 된다).

macOS / Linux 는 `./run-gui.sh`.

## 설치 (직접 하려면)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[ui,dev]"
```

## 사용법 (CLI)

```bash
# 1. 조건 목록 보기
chartfinder conditions
chartfinder conditions -k rsi_oversold      # 조건 하나의 파라미터 상세

# 2. 일봉 데이터 받기 (최초 1회, 이후엔 증분 갱신)
chartfinder update -m kr -u all -y 3
chartfinder update -m kr -u all -y 3 -w 12   # 동시 요청을 늘려 더 빠르게
chartfinder update -m us -u sp500 -y 3

# 3. 검색
chartfinder scan -m kr \
  -c ma_alignment \
  -c "ma_pullback:period=20,max_gap=3,weight=2" \
  -c "volume_dryup:ratio=0.7" \
  --top 20 --detail

# 프리셋으로 검색 + CSV 저장
chartfinder scan -p presets/pullback_buy.yaml --top 30 --csv out/result.csv

# 캐시 상태
chartfinder status -m kr
```

조건 문법은 `키:파라미터=값,파라미터=값,weight=가중치`. 파라미터를 생략하면 기본값을 쓴다.

`--detail` 은 조건이 5개 이하면 점수를 표 안에 열로 넣고, 그보다 많으면 종목별로
충족·근접·미달을 풀어서 보여준다 (가로로 욱여넣으면 읽을 수 없어서).

## 조건이 실제로 먹히는지 보기 (백테스트)

과거 시점까지의 데이터만 보고 채점한 뒤, 그 뒤 N영업일 수익률을 확인한다.

```bash
# 전략 하나
chartfinder backtest -p presets/oversold_rebound.yaml -m kr -u kospi \
  --horizon 20 --dates 40 --every 20 --top 30

# 전략 전부를 한 번에 비교 (조건 계산을 공유하므로 8번 따로 돌리는 것보다 훨씬 빠르다)
chartfinder backtest --all -m kr -u kospi --dates 40 --every 20
```

`--all` 은 이런 표를 낸다.

```
전략 비교 (|t| ≥ 2 라야 우연이 아니라고 볼 수 있다)
 전략            초과수익  초과 t      IC   IC t  초과승률  판정
 신고가 근접       +0.86%  +4.90  +0.113  +5.99      78%  신호 있음
 눌림목           -0.25%  -1.24  +0.035  +1.70      40%  구분 안 됨
 과매도 반등      -0.99%  -6.14  -0.110  -6.03      20%  역효과
```

보는 것은 세 가지다.

- **초과수익** — 상위 N종목의 이후 평균 수익률이 전체 평균보다 높은지
- **점수 구간별 수익** — 점수가 높은 구간일수록 수익이 올라가는지
- **기준일별 IC** — 하루 안에서 점수와 이후 수익의 순위상관. 그 평균이 0과
  다른지를 t값으로 본다 (|t| < 2면 "판단할 수 없음")

표본 수를 '종목 수 × 기준일 수' 로 세면 안 된다. 같은 날 종목들은 시장 전체
움직임을 함께 타므로 독립이 아니고, 그렇게 세면 4천 건짜리 표본처럼 보여도
실제 독립 단위는 기준일 수(10개 남짓)뿐이다. 그래서 날짜별 IC 의 t값으로 판단한다.

`--every` 가 `--horizon` 보다 짧으면 관찰 구간이 겹쳐 같은 국면을 여러 번 세게 되므로
경고한다.

미래 참조를 막는 것이 핵심이라, 기준일 이후의 봉은 채점에서 제외하고
재무는 **그 시점에 이미 공시됐을 결산기만** 쓴다 (사업보고서 제출 시한 90일 반영).

매매 비용·슬리피지는 반영하지 않고, 상장폐지 종목이 캐시에 없어 결과가
실제보다 낙관적으로 나올 수 있다.

전 종목이 같은 점수라 순위를 매길 수 없는 기준일은 '채점 불가'로 표시하고 통계에서 뺀다.
그런 날 상위 N을 뽑으면 점수가 아니라 종목코드 순서로 뽑히는데, 코스피에서 앞 번호는
오래된 대형주라 결과가 한쪽으로 기운다. 같은 이유로 동점은 무작위로 섞어 뽑는다.

검증 구간 내내 모든 종목에서 0점이던 조건은 따로 표시한다. 그 데이터가 구간을
덮지 못한다는 뜻이다 — 수급은 최근 120일치만 받고, **재무는 최신 스냅샷(3개 연도)
뿐이라 과거 기준일일수록 볼 수 있는 결산기가 줄어든다.** 2023년 시점에는 아예 없다.
재무 조건의 백테스트 결과를 읽을 때 이 점을 감안해야 한다.

## 사용법 (데스크톱 창)

파이썬 기본 내장 tkinter로 만든 창. 별도 설치나 브라우저 없이 바로 뜬다.
화면은 두 가지다.

### 기본 화면 — 지표를 몰라도 쓸 수 있게

```bash
chartfinder-ui
```

조건·파라미터·가중치를 전부 감추고 **1단계 시장 → 2단계 전략 → 3단계 찾기** 세 단계만 남겼다.

- 전략 이름은 "눌림목 — 상승 중 잠시 쉬어가는 종목" 처럼 **지표 용어와 쉬운 말을 함께** 적고,
  아래에 한 줄 설명과 쓰는 지표 갈래(추세·거래량 …)를 붙인다
- **기본은 전체 선택.** 조건을 다 넣고 보는 쪽이 보통이라 전부 체크된 상태로 시작하고,
  필요하면 체크를 풀거나 '전체 선택 / 전체 해제' 로 바꾼다. 조건 하나하나를 만지려면 고급 화면으로
- 여러 전략을 고르면 **전략마다 따로 채점**하고, 가장 잘 맞는 전략의 점수로 순위를 매긴다.
  결과에 그 전략 이름이 함께 나온다. 평균을 내면 서로 반대인 조건(신고가 근접 ↔ 신저가 근접)이
  섞여 어느 쪽도 만족하지 못하는 종목이 상위에 온다
- 필요한 데이터가 없으면 무엇이 없는지 알려주고 바로 받을지 물어본다
- 데이터 받는 동안 **`1,234 / 2,678 (46%)` · 경과 시간 · 남은 시간 추정**을 보여주고,
  **취소** 버튼으로 중간에 멈출 수 있다 (받아둔 데이터는 그대로 남는다)
- 결과는 순위·종목명·현재가·등락·**적합도(%)** 만. 줄을 두 번 클릭하면 차트가 열린다

### 고급 화면 — 조건을 직접 만질 때

```bash
chartfinder-ui-advanced
```

(기본 화면 오른쪽 위 '고급 화면' 버튼으로도 열린다)

- 위쪽에서 시장/유니버스를 고르고 **데이터 받기** → 끝나면 **검색**
- 왼쪽 조건 49개를 체크하면 파라미터 입력칸이 펼쳐진다 (가중치도 여기서)
- 결과 행을 **더블클릭**하면 캔들차트가 브라우저에 열린다
- 프리셋 불러오기, CSV 저장 지원
- 수집·검색은 별도 스레드에서 돌아가므로 창이 멈추지 않는다

```bash
streamlit run chartfinder/app.py
```

- 왼쪽에서 시장/유니버스를 고르고 **데이터 받기**로 캐시를 채운다

### 외국인·기관 수급

수급 조건은 일봉과 별도로 투자자별 순매수를 받아야 쓸 수 있다. **한국 시장 전용**이고,
종목당 요청이 1회 늘어나므로 수집이 느려진다.

```bash
chartfinder update -m kr -u all --flows
```

수급 수집에는 `pykrx` 가 필요하다 (의존성에 포함돼 있다). 0건으로 끝나면
실패 사유가 함께 출력된다.

수집 경로는 세 단계다. **네이버 JSON API** → **KRX 일별추이(pykrx)** → 옛 네이버 HTML 표
순으로 시도한다. 새 네이버 금융은 화면을 자바스크립트로 그려 HTML 에 표가 없으므로
JSON API 가 주 경로이고, KRX 는 차단이나 엔드포인트 변경으로 빈 응답을 주는 일이 잦다.
처음 받을 때는 최근 120일치만 받는다 (수급 조건이 보는 구간은 길어야 수십 일이다).

## 수집이 안 될 때

어디서 막히는지 단계별로 확인한다.

```bash
chartfinder doctor -m kr
chartfinder doctor -m kr --symbol 005930 --days 30
```

종목 목록 → 시세 → 수급(KRX·네이버) → JSON API 엔드포인트 탐색 → 재무 순으로
성공/실패와 실제 응답 형태를 보여준다. 엔드포인트가 바뀌었을 때 어떤 키가
오는지까지 찍어준다.

UI에서는 '수급 포함' 체크박스. 받지 않은 상태로 수급 조건을 쓰면 점수가 0으로 나온다.

### 조건 추가하기

`chartfinder/conditions/builtin.py` 에 함수 하나만 추가하면 CLI 옵션과 웹 UI 위젯이 자동으로 생긴다.

```python
@condition(
    "my_rule", "내 조건", TREND,
    params=(_p("period", "기간", default=20, min=5, max=120),),
    description="설명",
)
def my_rule(ctx: Ctx, period: int) -> float:
    return soft_gt(ctx.last(ctx.close), ctx.last(ctx.ma(period)))
```

`ctx` 는 해당 종목의 일봉과 지표 캐시를 들고 있고, 반환값은 0~1 점수다.

### 재무 데이터

재무 조건은 일봉과 별도로 연간 재무제표를 받아야 쓸 수 있다.

```bash
chartfinder update -m kr -u all --fundamentals
chartfinder update -m us -u sp500 --fundamentals
```

출처는 한국이 네이버 JSON API(안 되면 옛 기업실적분석 표), 미국이 yfinance 재무제표다. 종목당 1회 요청이라
시세보다 느리고, 캐시는 30일간 유지된다. 컨센서스(2025.12(E) 같은 추정치)는 실적이
아니므로 제외한다.

#### 영업활동현금흐름 (한국)

네이버가 주는 항목은 매출액·영업이익·당기순이익·영업이익률·순이익률·ROE·부채비율·
당좌비율·유보율·EPS·PER·BPS·PBR·주당배당금 뿐이고 **현금흐름이 없다.** 그래서 이 항목만
금융감독원 DART 에서 받는다.

```bash
setx DART_API_KEY 발급받은키        # Windows (새 창부터 적용)
export DART_API_KEY=발급받은키      # macOS / Linux
```

키는 [opendart.fss.or.kr](https://opendart.fss.or.kr) 에서 무료로 발급한다. 키가 없으면
이 경로를 건너뛰고 `positive_cash_flow` 만 0점이 된다 (나머지 재무 5개는 정상).
사업보고서 한 번 조회로 3개 연도를 얻으므로 종목당 요청은 1회다.

미국은 yfinance 재무제표에 현금흐름표가 들어 있어 6개가 모두 채워진다.

모든 종목에서 0점만 나온 조건은 검색 결과 아래에 **"채점되지 않은 조건"** 으로 표시된다.
조건이 안 맞은 것과 데이터가 없는 것은 다르기 때문이다.

### 종목 정보 (시가총액·물량·공매도)

거래대금과 회전율은 일봉만으로 계산되므로 따로 받을 게 없다. 나머지는 스냅샷을
받아야 한다.

```bash
chartfinder update -m kr -u all --profiles
```

종목별 요청이 아니라 **시장 단위 한 번**이라 빠르지만, 항목마다 출처가 달라
일부만 채워질 수 있다.

| 항목 | 출처 | 막히면 |
|---|---|---|
| 시가총액, 상장주식수 | FinanceDataReader 종목 목록 | 시세가 되면 이것도 된다 |
| 외국인 보유비중 | pykrx (거래소 외국인 한도 소진율) | KRX 차단 시 못 받음 |
| 공매도 비중, 공매도 잔고 비중 | pykrx | KRX 차단 시 못 받음 |
| 대주주 지분율 | DART 최대주주 현황 | `DART_API_KEY` 없으면 못 받음 |
| CB/BW·유상증자 잠재 물량 | DART 전환사채·신주인수권부사채·유상증자 결정 | 같음 |
| 유통주식수 | 상장주식수 × (1 − 대주주 지분율) | 대주주 지분율이 없으면 못 냄 |

받지 못한 항목은 `update --profiles` 실행 직후 **표로 0 이 찍히고**, 어느 출처가
왜 실패했는지도 같이 나온다. 더 자세히 보려면 `chartfinder doctor` 를 쓴다.

못 받은 항목을 쓰는 조건은 모든 종목에서 0점이 되고, 검색 결과 아래
**"채점되지 않은 조건"** 으로 표시된다.

두 가지는 애초에 받을 수 없어 대체했다.

- **대차잔고** — 거래소 회원사만 볼 수 있다. 성격이 가장 가까운 **공매도 잔고 비중**
  (아직 안 갚은 공매도 수량 ÷ 상장주식수) 으로 본다.
- **기관 보유비중** — 어느 곳도 공개하지 않는다. 대신 실제로 받을 수 있는
  **기관 순매수 누적 ÷ 상장주식수** (`inst_accumulation`, `--flows` 필요) 를 쓴다.

잠재 희석 물량은 공시 세 종류를 합쳐 센다. 사채는 신주 수를 안 주므로
**권면총액 ÷ 전환(행사)가액**, 유상증자는 공시에 적힌 **신주의 종류와 수**를 그대로
쓴다. 이미 전환·상환·발행된 물량은 공시만으로 알 수 없어 **상한**으로 봐야 한다.

## 구조

```
chartfinder/
  datasource/    시장별 어댑터 (krx / us / demo) — 공통 OHLCV 스키마로 정규화
  cache.py       parquet 로컬 캐시 + 증분 갱신
  indicators.py  기술적 지표 (pandas 벡터 연산)
  scoring.py     근접도 점수 함수 (soft_lt / soft_gt / ordered ...)
  fundamentals.py 재무 스키마와 정규화 (소스별 컬럼명 흡수)
  conditions/    조건 레지스트리 — 파라미터 스키마가 UI/CLI를 자동 생성
  screener.py    전 종목 채점 + 가중 랭킹
  backtest.py    과거 시점 채점 → 이후 수익률 (미래 참조 차단)
  charts.py      캔들차트 (두 UI가 공유)
  cli.py         커맨드라인
  simple_ui.py   tkinter 기본 화면 (조건을 감춘 초보자용)
  ui.py          tkinter 고급 화면 (조건 직접 선택)
  app.py         Streamlit 웹 UI
presets/         조건 세트 YAML
```

캐시 위치는 기본 `~/.chartfinder` 이고 `CHARTFINDER_HOME` 환경변수로 바꿀 수 있다.

## 알아둘 점

- **일봉 기준**이고 실시간이 아니다. 장중 데이터는 반영이 늦거나 빠질 수 있다.
- 데이터 출처는 무료 API(FinanceDataReader, yfinance)라 수정주가·결측 처리는 출처에 의존한다.
- 종목당 1회 요청이라 **시세·수급·재무 모두 동시에 8개씩** 보낸다(`--workers` 로 조절).
  세 가지 중 하나라도 순차로 남으면 나머지를 아무리 빨리 받아도 전체 시간이 줄지
  않는다 — 2,600종목 × 순차 1회 요청이 곧 전체 소요 시간이 되기 때문이다.
  너무 크게 잡으면 상대 서버가 막으므로 12~16 정도가 상한이다.
- 실제로 몇 배 빨라지는지는 직접 잴 수 있다. 무엇이 느린지에 따라 나눠서 본다.

  ```bash
  chartfinder speedtest -m kr --what prices        # 시세
  chartfinder speedtest -m kr --what flows         # 수급
  chartfinder speedtest -m kr --what fundamentals  # 재무
  ```

  동시 요청 수를 바꿔가며 종목/초와 전 종목 환산 시간을 재고, 서버가 동시 요청을
  받아주지 않으면 그렇다고 알려준다. `update` 는 끝날 때 단계별 소요 시간과 실제
  동시 요청 수를 함께 찍으므로, 체감이 아니라 숫자로 비교할 수 있다.
- 미국 전 종목(`-u all`) 최초 수집은 수십 분이 걸린다. `sp500` 으로 시작하는 걸 권한다.
- 투자 판단 도구가 아니라 **후보 탐색 도구**다. 결과는 반드시 직접 검증할 것.
